MECANISMOS PARA ENVIAR LOGS DE NFTABLES A SPLUNK

Existen 2 enfoques (que pueden fusionarse):

1. Trámite por Red (Vía HEC de Splunk):
   - Flujo actual: nftables -> buffer del kernel (dmesg) -> script forwarder -> Splunk HEC.
   - Estado: Es lo que soporta la configuración actual por defecto.

2. Trámite por Archivo Físico Compartido (Volumen Docker):
   - Flujo nuevo: nftables -> demonio ulogd -> archivo físico (/var/log/nftables/nftables.log) -> volumen compartido -> Splunk.
   - Ventaja: Permite a Splunk leer directamente el archivo en tiempo real.
   - Requisitos de implementación (cambios necesarios):
     * dockerfile: Instalar 'ulogd'.
     * ulogd.conf: Crear este archivo para configurar la salida del demonio.
     * entrypoint.sh: Iniciar el demonio 'ulogd' en background antes de cargar el firewall.
     * rules.nft: Agregar 'group 0' a las reglas de log para redirigirlas del kernel hacia ulogd.

* NOTA IMPORTANTE (Si se desean usar ambos a la vez):
Al implementar ulogd, los logs ya no van al kernel (dmesg).
Para que el envío por red (HEC) siga funcionando, el script en el entrypoint.sh
debe modificarse para hacer un 'tail -F' al nuevo archivo generado por ulogd en lugar de usar 'dmesg'.
